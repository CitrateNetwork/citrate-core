# Citrate Core 0.5.2

> Draft. This file is the source for the GitHub release body. It is final only when every step
> on the 0.5.2 release checklist is done. The bracketed values (chain commit, genesis hash,
> build commit) are filled in at the cut from the bundled node and the tag, never by hand.

0.5.2 moves the app to the restarted test network (r1006) and is a **required update**: earlier
builds cannot sync or sign on it. It also adds your own cloud model keys for Hermes, a single
invite flow, honest sync progress and a free-node-first setup. Your wallet, keys and settings are
kept.

## Required update: the test network restarted (r1006)

- **New genesis, same chain id.** The test network restarted on a new genesis (r1006, chain id
  40204). 0.5.2 ships a network profile for it and its bundled node runs r1006. (#363, #518, #578)
- **Earlier builds stop safely.** A build made for the previous network shows "Update required"
  and does not sync or sign anything. Use the update card in the app, or download 0.5.2.
- **What the update keeps.** Your wallet, keys, settings and local pins are kept. Values that
  belong to the previous network are kept apart and never shown as current on the new one.
  (#442, #499, #505, #511)
- **A genesis check before every signature.** The app compares the network's block 0 with the
  profile it was built for before it signs, and refuses on a mismatch. (#363)
- **Settings › Network** shows the network this build targets: name, chain id, RPC, explorer and
  bootnodes, all read from the network profile. (#515)

## Hermes: your own cloud model keys

- **Bring your own key** for OpenAI, Anthropic, Google Gemini, xAI, DeepSeek and Meta (Muse models
  on the Meta Model API). Hermes › Controls › Details › Models connects, tests and removes a key;
  a key is stored only after its live test passes. (#530, #531)
- **Keys stay on this device.** Keys are held in the system keychain. Hermes runs its agent loop
  on a cloud model through a proxy inside the app, so the key never reaches the Hermes helper
  process, logs or diagnostics. Calls go only to the vendor's own endpoint; a custom endpoint is
  labelled unverified and needs your confirmation. (#528, #529, #532)
- **Spending caps and a usage view.** Set a cap per vendor; calls past it are refused, and an
  unusual spike pauses calls until you resume. Every call is recorded in a usage log on this
  device, and Models shows usage and spend from it. (#529, #531, #535)
- **Delegate to Devin (Cognition).** Hermes can hand a task to Devin when you connect a Cognition
  key. Each delegation shows the exact scope and waits for your approval, and its results are
  treated as untrusted. (#532)
- **MCP server secrets** move from a settings file into the system keychain; existing entries are
  migrated. (#528)

## Groups: one invite flow, request and approve

- **Invite someone** makes a one-time link. Whoever opens it asks to join, and you approve or
  decline the request in Groups › People. (#549)
- Earlier invite links (short links, rendezvous and self-admit) are removed. Invites made by an
  earlier version are set aside on disk, kept and readable only by you, and are not carried over
  as working invites; send a new invite. (#549)

## Node

- **Sync progress you can read.** While the node catches up, the status line shows how many
  blocks behind it is, the measured catch-up rate and an estimate, or says plainly when it is not
  catching up or cannot read the network head. (#566, #569)
- **Node page:** Status, Services, Storage, Rewards and Advanced tabs, with a services registry
  that shows what is running. (#563, #509)
- **Steadier helper processes.** Start and stop controls for the app's helper processes are
  acknowledged, and readiness is checked before a helper is used. (#351, #352, #367, #344)
- **Storage:** files, memory, local pins, and verified export and restore. (#368)

## Setup: running a node is free

- Setup now starts with the free path: running a node, a wallet and Hermes on this machine does
  not need a membership. Membership is optional and can be chosen during setup or later; its
  price appears only at checkout, and only when it has been read from the membership service.
  (#576, #590, #579)

## Wallet and money screens show only what is read

- Every on-chain figure on the Wallet, Node and setup screens is shown only once it has been
  read. A value that has not been read shows as unknown, never as zero, and a feature that is not
  running on the network is labelled as not running. (#347, #348, #555, #556)
- One explanation of how the membership grant is held, one source for the membership price, and
  wallet copy that names the device key the app actually uses. (#349, #545)
- Sends use estimated gas instead of fixed limits; the send record is kept per network; a payment
  whose outcome is not yet known is shown as unknown. (#516, #513, #554)

## Also in this release

- Hermes Work and Learn tabs, and Controls at three depths. (#341, #364)
- Store: a signed catalog check and paused installs; per-session tool sets for Store daemons.
  (#356, #376)
- Deep links reach the running app on Linux and Windows. (#346)
- Opt-in, anonymous setup-progress events. (#365)
- Dependency updates for published advisories (crypto-bigint, webpki). (#492, #383)
- Hardening of local secret handling and several crash, restart and concurrency paths.

## Known issues

- **Checkpoint finality is not in this release.** Blocks are not yet finalized by validator
  votes.
- **Desktop block production stays off** until the network runs at least two other live
  producers.
