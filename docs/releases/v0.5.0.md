## Update to rejoin the network

Citrate Network has moved to a new chain (chain id 40204, new genesis `[genesis hash]`).
Citrate Core 0.4.x and earlier follow the retired chain and cannot rejoin. Update to 0.5.0 to
reconnect.

- **Your keys and wallet stay.** The update keeps your wallet, your node's identity keys and
  your settings.
- **Your node resyncs from the start.** On first launch 0.5.0 sees the chain change, removes the
  old chain's block data (only the chain database; keys and settings are kept) and syncs the new
  chain from block 0. The app tells you once: "Citrate Network was upgraded to a new chain; your
  node is resyncing from the start".
- **macOS and Linux:** the app offers the update itself (Update available, then Restart now).
  **Windows:** there is no in-app updater on Windows yet. Download the 0.5.0 installer and run it.

## What's new since 0.4.2

0.5.0 is the Hermes upgrade. The work landed in six internal milestones on the 0.5.0 line (only
0.4.2 was released along the way), summarized here by what you can do.

### Hermes is one agent everywhere
- One Hermes session is shared by the app, the `citrate-agent` command line and MCP clients;
  you can follow a session from the terminal and the app picks a running session back up after a
  reload.
- The agent loop runs in the Hermes sidecar by default, with streamed replies.
- Plan it first: Hermes interviews you, writes a brief you can edit, and checks its own results
  with verifiers (an HTTP status, a file hash) rather than taking its own word for "done".
- The app picks a model tier from your hardware and sizes the local model's context and GPU use
  to match.

### You stay in control (HIC)
- **Terminal access with per-command approval.** Hermes can run command-line tools (build, test,
  lint, inspect) in folders you have shared with it. Every command is shown to you exactly and
  runs only after you approve it, in the operating system's sandbox with no network. It is on by
  default; turn it off in Settings > App > "Let Hermes run terminal commands".
- Folder grants: Hermes reads and writes only in folders you share, and file changes can be undone
  from a checkpoint.
- Web sign-in budgets: Hermes signs in to web apps only within a budget you set, with a hardened
  sign-in message check.
- Approval cards now also cover MCP tools, terminal commands and contract deployments.

### Knowledge, personas and skills
- A bundled Citrate knowledge corpus is imported on first run, so Hermes can answer questions
  about Citrate with citations.
- Six personas and five learning tracks with guided workflows.
- Verified self-learning: Hermes keeps a skill only after a verifier confirms it worked.

### MCP and the web
- Hermes can use MCP servers you add, with an approval card for any tool call that changes
  something.
- Your node runs an MCP server that other agents (for example Claude Code) can use, with a
  read-only token for Hermes by default.
- Pop-out windows: a Code and diff view, a Contract reader and an Activity monitor that shows the
  plan, approvals, verifier results and tokens per second.
- A managed browser and private web search are included behind a switch that is off by default.

### Build on Citrate
- Contract and dApp templates, a deploy gate that only lets a deployment through after its tests
  and checks pass, and a deploy you approve through the signing ceremony.
- Read-only contract views on 40204.

### Chain-native identity and the new network
- **Member-minted AgentSBT.** You mint your agent's identity token from your own wallet, using your
  membership SBT, through the signing ceremony. No one mints it for you and no key goes near the
  agent.
- **Agent precompiles active from genesis** on the new 40204 chain (LoRA apply and merge, memory
  anchor verify, agent operations).
- The app reads every contract address from the canonical address book generated from the chain
  release; nothing is hard-coded.
- Nightly anchoring of Hermes's decision records, with "Prove a past decision" in the app. Each
  anchor transaction needs your approval. It has been tested on a local chain; the first anchors on
  the new 40204 chain come after launch.
- A daily metering report and on-chain receipts for Hermes's spend.

### Your machines and everyday tools
- Connect-my-machines wizard with per-device keys, pairing by link or QR code.
- **Model delete.** Remove a downloaded model from the Models screen. The app refuses, with a
  reason, while the model is in use, still downloading or shipped with the app, and tells you how
  much space was freed.
- Downloads resume after a dropped connection or a restart, and Hugging Face tokens work for gated
  models.
- Daily journal with a Hermes summary and encrypted export; Google Sheets and Calendar tools;
  sandboxed widgets and budgeted background tasks.
- A device-key recovery kit, "Delete my local data", and crash reports that are sent only when you
  review and press Send.
- Accessibility pass on pop-outs and approval dialogs.

### Process cleanup safety improvements
0.5.0 includes process cleanup safety improvements in how the app starts, stops and updates its
helper processes:
- The app checks, before it starts the node after the chain change, that no older Citrate node is
  still running or holding the chain database; if one is, the app names it instead of stalling.
- Quitting stops the embedding server together with Hermes, including when Hermes fails to start.
- The Windows installer stops this installation's own helper processes before it replaces files.
- Further process cleanup safety improvements in the app and the Hermes runtime.

The lifecycle design behind these fixes, and much of the evidence for them, is by
@mfarzanansari. Thank you.

## Known issues

- **Chat may switch to the gateway without asking.** When your local model is downloaded but its
  server is not running, and a gateway key is configured, chat sends your message to the gateway
  without asking first. Fixed in 0.5.1: chat will ask you each time (restart the local model, or
  send this message to the gateway).
- **Helper process supervision.** Retry limits, health-check timing and log size limits for the
  helper processes are improved in 0.5.1.
- **Some helper processes can outlive a stop.** Processes started by some helper processes (for
  example by Hermes's tools) may keep running after you stop Hermes or quit the app, until 0.5.2.
  Restarting your computer clears them.
- **Windows has no in-app updater.** Windows members update by downloading and running the
  installer.
- Some features are off by default or need a later step: the managed browser and web search
  (switch, off), the deploy-gas faucet (off), the fleet mesh (off), skill publishing, and the
  contract analysis tools for the deploy gate, which arrive as a signed component update.
