# Citrate Core 0.5.1

> Draft. This file is the source for the GitHub release body. It is final only when every step
> on the [release checklist](https://github.com/CitrateNetwork/citrate-core/issues/328) is done.
> The bracketed values (chain commit, consensus fingerprint, build commit) are filled in at the
> cut from the bundled node and the tag, never by hand.

0.5.1 is a network-safety update for macOS, Linux and Windows. It keeps desktop nodes on the
network's chain and makes the Linux package replace older installs cleanly. It is also the first
Windows release of the 0.5 line. Your wallet, keys and settings are kept.

## Linux .deb users on 0.4.2 or earlier: install 0.5.1 by hand

Linux .deb builds 0.2.5 through 0.4.2 (and the early `citrate` 0.1.0 package) can end your
desktop session when they start. 0.5.0 fixed that, but an older build cannot update itself
safely, so install 0.5.1 directly:

```bash
sudo apt install ./Citrate-Core-linux-<arch>.deb
```

or run the one-line installer from citrate.ai/download. It stops and prints the removal command
if an older Citrate Core package is still installed. The 0.5.1 .deb replaces the old `citrate`
package and its menu entry. If you are already on 0.5.0, the in-app update works as usual.

## Windows

0.5.1 is the first Windows build of the 0.5 line (Windows skipped 0.5.0).

- **Install by download.** There is no in-app updater on Windows yet. Download the installer from
  citrate.ai/download and run it. Your wallet, keys and settings from an earlier Windows install
  are kept.
- **The installer is not code signed yet.** Microsoft SmartScreen may warn on first launch;
  choose "More info", then "Run anyway", if you trust the download source.
- **Not yet certified.** The installer was checked on a clean Windows virtual machine; hands-on
  checks on members' Windows computers have not been run yet.

## What's new since 0.5.0

### Your node stays on the network's chain
- **Block production only when the network agrees.** A desktop node seals blocks only when at
  least two other producers are live, the network's newest block is recent, your node is caught
  up, and it agrees with the network on the chain. Otherwise production stays off, and the Node
  screen shows the reason. Today the network runs one producer, so desktop block production
  stays off for now. (#329)
- **Automatic move off a withdrawn branch.** If your node's data holds blocks from the branch the
  network withdrew in October, the app turns block production off, stops the node, moves only
  the chain database aside (into `node.withdrawn-<date>`), keeps your keys and node settings, and
  resyncs from the network. It tells you once. A node that is on the network's chain is never
  touched. (#331)
- **The bundled node refuses blocks that contradict the network's history.** The node carries the
  network's canonical blocks at the October rollback point and refuses any other block at those
  heights, and anything built on one. (CitrateNetwork/citrate-chain#311)
- **Steadier consensus with more than one producer.** The node scores merge blocks from a bounded
  window, so nodes with and without pruning reach the same result; checks a block's producer
  against the validator set of the block's own epoch; and no longer seals a burst of blocks after
  catching up. (CitrateNetwork/citrate-chain#306, CitrateNetwork/citrate-chain#307, CitrateNetwork/citrate-chain#313)

### Linux
- The .deb replaces the old `citrate` package and its menu entry, so `apt install` no longer
  leaves an older build in place. (#334)
- The app writes one line to its log at start-up naming the WebKitGTK graphics settings it
  applied, to help with display problems on some GPUs. (#330)

### Dependencies
- zip 9 (RUSTSEC-2026-0367, RUSTSEC-2026-0368, RUSTSEC-2026-0369) and rustls 0.23.46.

## Known issues

- **Windows has no in-app updater and is not yet certified.** See the Windows section above.
- **Windows: no sandboxed terminal commands yet.** On Windows, Hermes declines terminal commands
  and says why, because the Windows sandbox is not built yet.
- **Checkpoint finality is not in this release.** Blocks are not yet finalized by validator
  votes. This is planned separately.
- **Desktop block production stays off** until the network runs at least two other live
  producers.
- The helper-process supervision, finer-grained knowledge-import resume and Hermes building
  features listed for "0.5.1" in the 0.5.0 notes now arrive in 0.5.2.
