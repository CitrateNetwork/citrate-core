# B1.3 — wagmi/EIP-1193 ceremony connector (D-13)

## What B1.3 is
A custom wagmi connector wrapping an internal **EIP-1193 provider** so the React app's
signing calls (`personal_sign`, `eth_signTypedData_v4`, and `eth_sendTransaction`) resolve
ONLY by routing through `bridge.signing` → the Rust SignatureCeremony → approval. **Signing
never happens in JS**: the connector holds no key, does no crypto, and only marshals an
intent to the bridge and returns the signature the ceremony produced. Reads stay on the
existing viem http transport (no ceremony).

## What B1.3 is NOT
- Not the real on-chain broadcast of `eth_sendTransaction` (that is B1.4 — and note the
  recoverable EIP-155 signer is `native`-gated in wallet-core, not in citrate-core's lean
  build; B1.4 resolves that). B1.3 routes `eth_sendTransaction` INTO the ceremony but the
  broadcast leg is an honest "deferred to B1.4" (no faked send — Rule 1).
- Not the micro-app EIP-1193 provider hand-off (CORE-S6.5).

## Design
- **EIP-1193 provider** (`request({method, params})`):
  - **Reads** (`eth_call`, `eth_chainId`, `eth_blockNumber`, `eth_getBalance`, `eth_getTransactionReceipt`, …) → forward to the viem http transport for 40204. No ceremony.
  - **`eth_accounts` / `eth_requestAccounts`** → the wallet address from the bridge (wallet domain); never a private key.
  - **Signing** (`personal_sign`, `eth_signTypedData_v4`, `eth_sendTransaction`) → build a
    `SignatureIntent {origin, kind, chainId, raw}`, call `bridge.signing.request(intent)` →
    render the ceremony (the existing ceremony UI) → on user approval call
    `bridge.signing.approve(id, rawAck)` → return the signature. Rejection → EIP-1193 user-
    rejected error (4001). `eth_sendTransaction` gets the signature via the ceremony, then
    the broadcast leg returns an honest "not yet wired (B1.4)" error, not a fake hash.
  - **Origin integrity:** the `origin` in the intent is the true caller origin; the ceremony
    (Rust) displays it. The connector never sends a caller-claimed "benign" flag.
- **wagmi wiring:** replace `connectors: []` in `src/wagmi.ts` with `[ceremonyConnector]`.
- **No key/crypto in JS:** the connector delegates every signing decision to the bridge;
  a source check proves no signing/private-key logic exists in the connector or anywhere in
  `src/`.

## Acceptance (Rule 11)
- A `personal_sign` via wagmi resolves only after a ceremony approval (data source: the
  `bridge.signing` request/approve round-trip).
- No signing/private-key logic in `src/` (data source: source scan).
- Reads resolve via the viem transport without a ceremony (data source: connector flow).
- `eth_sendTransaction` routes to the ceremony and honestly defers broadcast (data source:
  connector flow; no fabricated hash).
