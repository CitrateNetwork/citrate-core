## Why this run happened

On 2026-10-04 the owner wrote: "If they are on this list they are important and need to be in the
0.5.0 release. Please lets rescope everything and get a clear overview of whats left and then we need
to fan out and get it all done." A planner re-read all 106 playbook items and gave each a verdict:
6 done, 8 obsolete, 2 decided, 19 built in open PRs, 21 buildable, 14 owner, 36 external. It then
cut the 21 buildable items (plus the agent prep inside many external rows) into 19 lanes. Every
owner call a lane touched was built as the planner's recommended default, marked "pending owner
sign-off", behind a default that changes nothing risky for members.

## What went well

- **The rescope paid off.** Starting from one sheet with a verdict per item meant every lane knew
  which rows it could close and which it could only prepare. Lanes reported "prep" honestly in most
  cases, and the remaining list below is short on agent work for the first time.
- **Reviewers found real defects, again.** Each of these was in unmerged branch code and is fixed
  on the branch, with a test that fails first:
  - a race in the headless dispatcher lease that could tell the agent an approved action did not
    run when it did (L01, the one High of the run);
  - a duplicate-name guard in zip unpacking that a forged end record could bypass (L12);
  - the ceremony could have trusted a gated ABI for runtime code the gated build never deploys (L05);
  - an environment variable inherited from outside the app could keep trajectory recording on
    while the panel said off (L10);
  - the recall filter for unresolved learned memories missed the titles the daemon actually prints,
    and `memory.neighbors` was not filtered at all (L02);
  - a regenerated address book would have pinned the existing InferenceRouter and turned on the
    HIC-1 registry route before the US-1.5 decision (L03);
  - an open metering turn kept a sampling thread running for the life of the process (L06);
  - `readOwner` turned RPC failures into "no owner" (L17);
  - the persona picker still told members the names were placeholders (L19).
- **Mutation checks keep earning their place.** Reviewers broke between 4 and 21 guards per lane.
  Guards that survived the builder's own tests: the D-7 hostname privacy check in sizeup (it passed
  with the flag flipped), the macOS re-dial port fix, the broadcast observer call, the
  `wallet_list` parse error, the Journal > Sheets Undo wiring, a workflow-run guard on chat plan rows,
  and `register_gated_abi`'s READY and code-equality checks. Each now has a test that kills it.
- **Real tools found real bugs.** Driving the hello-mint workflow through a real sidecar showed
  Hermes could never get its own template to READY: the toolchain refused every template's
  `medusa.json`, Aderyn could not find solc, Medusa could not start crytic-compile under the
  sandbox, and Medusa's own output file broke the report binding. A Gemma-scale devnet round at
  release speed hit the node's per-client rate limit. The real BGE server, the real CfT zip and a
  real sd-server image run all went through the shipped code paths.
- **The stackers caught the joins.** Core: the `seed` field name in a new cluster DTO tripped the
  invoke secret-scan test; L12 and L13 both extended the managed-browser environment; L10's held-out
  manifest was not a dataset eval-check knew. Chain: a benchmark file named an audit finding id and
  failed `check_claims`. Each was fixed on the owning lane branch and re-merged upward with signed
  commits, no rebase and no force-push.

## What went wrong

- **`git stash` again.** L05 ran `git stash` for a baseline; the stash list is shared across
  worktrees and L05's and L06's entries were swapped. Both lanes recovered by SHA and lost nothing,
  but this is the third run with a stash incident after the brief said not to (A61 was not enough).
- **Processes killed by pattern.** L03 ran `pkill -f "git status --short"` to clear its own index
  lock, and the chain stacker killed `cargo test` and `cargo clippy` by pattern. Both were likely
  harmless; both could have stopped another lane's run.
- **The GPU was lost for the rest of the day.** A T1 llama-server stopped by L08 froze while exiting
  and still holds about 21 GB of GPU memory, and an older Gemma server from another lane is frozen
  the same way. Every model load since fails. Only a restart frees it, so ra-1, the T1 half of ra-16
  and US-9.2, and the T1 web score are blocked on a person, not on code.
- **Shared targets and machine load.** Load averages of 20 to 70 made timing tests flaky in core,
  kit, sidecar, identity and docs (each passed alone). Several lanes saw another worktree's kit in
  the shared core target; two built in private target dirs and deleted them after. A55 is still open.
- **A bug that vitest could not see.** `harness.ts` imported `./knowledgeSearch` without its `.ts`
  extension, so every eval script crashed under plain Node while vitest stayed green. L08 and L09
  found it independently on the same day. Both added a test that starts the scripts for real.
- **Stale facts in the brief.** L07's override said `citrate-sizeup` had no remote; the reviewer
  found the private repo had been created that evening. L08's runs were not set up the way the lane
  asked (the app's llama-server running alongside, ctx 8192); the run record says so.
- **Two packaged-app runs skipped for good reasons.** L15 could not build a packaged release above
  the 12 GB disk floor, and a local-run build shares the bundle id with the owner's installed app,
  so the recovery-kit and import steps would have touched his real wallet. That was the right call;
  it leaves the click-through with a person.

## What surprised us

- `rpc.citrate.ai` returns null for `eth_getTransactionByHash` and `eth_getTransactionReceipt` for
  transactions that are in its blocks. Forge receipt polling and the book and provenance tools all
  depend on those calls, so the F-4 redeploy cannot run against it today.
- The committed provenance ledger is missing deployer nonces 116 and 117 (two plain transfers).
- A top-level `eth_call` to a precompile address returns `0x` on a Citrate node, so the node MCP
  `precompile_call` and `ed25519_verify` tools could never return a real answer. `precompile_call` now
  says so instead of returning `0x` as a result; routing calls through contract code is a design call.
- Gemma 4 E4B spends the whole 160-token self-review budget on reasoning and returns no content.
- Homebrew's llama-server cannot load Gemma 4; the app's bundled one can.
- On macOS, re-dials that reused the listen port failed while the old connection sat in TIME_WAIT,
  so a peer refused once could never get back in from a Mac. The existing late-link test was red on
  the base on macOS.
- T0 literacy is well below the bar: 51.2 % pass and 70.3 % citation hits on the tool path, 43.9 %
  and 59.5 % through the sidecar. Most misses are correct answers in other words, or citations of
  Gradient Paper No. 2 instead of the docs page the key wants.
