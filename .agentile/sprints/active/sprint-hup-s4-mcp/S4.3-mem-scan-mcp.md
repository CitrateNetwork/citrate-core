# HUP-S4.3: mem-mcp and CitrateScan as Hermes MCP servers, plus get_verified_source

Planset: `.agentile/planset/2026-09-30-hermes-upskill/` (04_FEATURES_BDD US-4.1 AC1 and
US-6.3 AC1; 05_SPRINTS_AND_WPS S4.3). Builds on HUP-S4.1 (`agent-mcp-host` in
citrate-agent-runtime, allowlist file named by `CITRATE_HERMES_MCP`).

## What shipped

Branches `hup/n4-mem-scan-mcp` in citrate-core, citrate-explorer, citrate-agent-runtime.

- **Allowlist writer** (`src-tauri/src/hermes_mcp.rs`). Core renders the S4.1 host's JSON
  allowlist from the member's settings (`hermes/mcp-settings.json`), writes it `0600` as
  `hermes/mcp.json`, and removes it when nothing is enabled. `hermes.rs` passes
  `CITRATE_HERMES_MCP` to the sidecar only while the file exists, and re-syncs the file before
  every Hermes start. Both entries set `allow_write_tools = false`.
- **mem-mcp** is offered through a read-only stdio bridge (`src-tauri/src/mem_mcp_bridge.rs`):
  the allowlist names the citrate-core executable itself with `--citrate-mem-mcp-stdio
  <socket>`, and `main.rs` runs the bridge before any app start-up. The bridge lists only the
  seven read tools (recall, search, neighbors, as_of, verify, critique, analogy), marks them
  `readOnlyHint: true`, and answers any other `tools/call` locally without reaching the daemon.
  Only `initialize`, `ping`, `tools/list`, `tools/call` and notifications pass.
- **CitrateScan** is offered as an HTTP server at `https://explorer.citrate.ai/api/mcp` (the
  host pinned in `activity.rs`).
- **get_verified_source** agent tool (`src/agent/verifiedSource.ts`, store handler, harness
  tool + annotation `none/untrusted`, Tauri command `contract_verified_source` in
  `src-tauri/src/verified_source.rs`). Core calls the explorer's new
  `GET /api/contract/{addr}/source`; on 404 (an explorer deployment without that route) it
  reads the `verification` field of `GET /api/contract/{addr}`. Statuses: verified,
  partial-match (never verified), unverified, unavailable (never reported as unverified). An
  unknown status is an error. Source, ABI, contract name and compiler string reach the model
  only inside the untrusted-data fence.
- **Agent surface**: a "Connected tools (MCP)" card with one switch per server, the reason a
  server is unavailable, and a restart note while Hermes is running.
- **citrate-explorer**: `getVerifiedSource` in the shared tool registry (so `/api/mcp` and the
  in-app agent both get it), the lean REST route, and MCP tool annotations on every tool.
- **citrate-agent-runtime**: the parity fixture gains the new core tool (sha pin bumped in both
  repos, bytes identical).

## Owner decisions (built with safe defaults)

- Both servers default **off** (pending owner sign-off). Members see no change until a switch
  is turned on. Turning either on by default is the owner's call.
- The CitrateScan entry sends the addresses Hermes looks up to explorer.citrate.ai. The card
  says so.

## Not done

- Production CitrateScan does not yet send tool annotations, so until this explorer branch is
  deployed the S4.1 host offers **no** CitrateScan tools (it treats unannotated tools as
  writes). `get_verified_source` works today through the fallback route.
- The settings card does not show the sidecar's live per-server state (`GET /mcp/servers`);
  it shows the member's choices and whether the file is written.
- User-added servers (S4.4) are not part of this WP; they should extend `render_config` rather
  than write a second file.
- The explorer does not store optimizer settings or EVM version, so compiler metadata is the
  solc version and source hash only.
