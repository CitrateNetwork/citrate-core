# HUP-S9.4, the rest: named rounds, round results, re-apply after a restart

Follows [S9.4-fl-rounds.md](S9.4-fl-rounds.md) (not edited). That record's "not done" list named
four gaps: live rounds, adapter download, an in-app eval run, and re-applying an adapter after a
restart. This WP closes the restart gap and connects the core side to the local-devnet round flow
the planset calls for (02_ARCHITECTURE section 9, 04_FEATURES_BDD US-9.1 AC1 and AC5). It does
not depend on another branch: the interface is citrate-chain `docs/fl/FL_ROUND_V1.md` (branch
`hup/n5-chain-fl`), and the only thing taken from that branch is one receipt file, copied as test
data.

| Remembered adapter | `active` in `<app data>/fl_rounds.json` |

## What shipped

- **Named rounds and per-round consent (D-29).** `RoundProposal` takes an optional `roundId`
  (0x plus 64 hex, validated, lowercased, bound into the plan hash; a proposal without one hashes
  exactly as before). The plan's compute paragraph and the approval card say what joining a
  named round does. An approved start writes the round into the worker's consent file first and
  then records the start; if recording fails, the consent is taken back. A round can be consented
  to once until it is withdrawn. Starts and withdrawals are serialized, so a rollback never
  removes another start's consent. An unreadable consent file is never overwritten.
  `fl_round_consent_revoke` withdraws consent (it lowers authority, so it needs no card) and
  marks the start record. The receipt names the file and says plainly that the worker is not
  bundled, so no training starts from the app.
- **Round results bind an adapter to its round.** `parse_round_result` reads a round result
  strictly and refuses it unless the round is Accepted, at least three devices took part, the
  chain, bundle and independent-replay record digests agree, the replay found no mismatch and
  checked the merged adapter, and every round id in it agrees. The gate takes an optional
  `roundResultPath`; with one, the expected hash may be left empty (it is the round's merged
  adapter) and a typed hash that differs is refused. The gate record carries the round
  (`round`: round id, record digest, chain id, ledger, device count), shown in the panel and in
  the gate summary. Core does not read the ledger itself: on 40204 it is not deployed, and a
  devnet is throwaway.
- **Re-apply after a restart.** A load is remembered. When the app starts the local model
  (`model_serve_start`), core puts the adapter back through the same checks as a load (latest gate
  record ACCEPT for the served base, copy re-hashed), only on the base it was loaded on. Unload, a
  later REJECT, an ACCEPT measured on another base, or switching the base while it is loaded ends
  that; a later re-ACCEPT does not bring it back without a new load. A failed re-apply never
  blocks the start and is shown in the panel.
- **Hermes.** `fl_round_plan` takes `roundId`; the plan text and the `fl_round_start` card name
  the round and its consent.
- **Formal.** `formal/FlRoundGate.tla` gains `saved`/`savedBase` (the remembered adapter), a ghost
  `wanted` (the member's standing intent), `AppRestart` and `Restore`, and the invariant
  `LoadedIsWanted`. New reach config `FlRoundGate_ReachRestore.cfg`.

## Not done here

- Live rounds on 40204: no deployed ledger, no member-facing coordinator, and the device training
  worker is not bundled in the app (S9.1/S9.2, DGX and chain operator).
- Adapter download from LoRAFactory / ModelRegistry (F-4). The gate takes a local file.
- Reading the round's status from the ledger by RPC: blocked on a deployed `FederatedRoundLedger`.
- Running the candidate eval inside the app: the eval CLIs are Node scripts and the packaged app
  has no Node runtime. The member or operator still runs them against llama-server with `--lora`.
- An eval delta from a real trained adapter: the devnet round used a fixture trainer that learns
  nothing, so its merged adapter is a protocol proof, not a better model.
- A packaged-app click-through of the new consent list and re-apply.
