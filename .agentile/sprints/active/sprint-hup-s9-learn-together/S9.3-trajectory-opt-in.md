# HUP-S9.3 (core): the member's opt-in for training on verified conversations

Fan-out 7 lane L10 (fl-learn-prep). Items: RA-15, US-9.1 AC1 (S9.3 opt-in), F-11 and g4-fl
preparation. The live round itself still needs the DGX team and the chain operator.

## What changed in core

- `src-tauri/src/fl_trajectories.rs`: the switch "Train on my verified conversations", stored in
  `<app local data>/hermes/trajectory-settings.json`. **Default off.** A missing, unreadable or
  corrupt file counts as off.
  - Off: core passes `CITRATE_HERMES_TRAJECTORIES` to the Hermes sidecar pinned empty, which
    overrides any value inherited from core's own environment, so nothing is recorded, and `trajectories_dataset_build` refuses before reading or writing anything.
  - On: the sidecar records verified, redacted turns into `hermes/trajectories/` (its existing
    S9.3 export: verified turns only, tainted sessions dropped, redaction always on). The member
    can assemble the newest of them, capped by the round's `maxTrajectories`, into one new
    `0600` file under `hermes/fl-datasets/` for the device training worker
    (`CITRATE_FL_DATASET`, after compute-pool's `citrate-fl-dataset` converts it).
  - Turning it off deletes the assembled training sets at once and, if the member ticks the box,
    the recordings too. Recording changes apply at the next Hermes start.
  - This switch never shares anything by itself: joining a round still writes that round's own
    consent (D-29, `fl_rounds.rs`), and nothing here uploads.
- Commands `trajectories_settings_get`, `trajectories_settings_set`,
  `trajectories_dataset_build`, each in `permissions/main-window.toml`.
- `src/fl/TrajectoryConsent.tsx` inside the federated rounds panel; the bridge methods on
  `FlRoundsDomain` (the browser preview refuses them, Rule 1).
- The round plan's data paragraph now names the switch and its off default instead of saying the
  export is not wired.
- `src/agent/eval/heldout.ts` and `toolcall-v2.heldout.json`: the toolcall-v2 held-out manifest
  (hashes of normalized prompts, no prompt text). compute-pool's converter drops any training
  example that matches it, so the S9.4 eval delta is never measured on trained items.
