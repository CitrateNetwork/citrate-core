## Acceptance criteria and how each is checked

| # | S14.6 criterion | Check (scenario in `scripts/ci/linux-native-acceptance.sh`) |
|---|---|---|
| A1 | AppImage **and** `.deb` | Both kinds run through every scenario below, each with its own HOME |
| A2 | Launch | `launch`: the app stays up and the node sidecar (`citrate`) runs under it within the timeout; the sidecars it starts unprompted and its window are recorded |
| A3 | Quit | `quit`: `WM_DELETE_WINDOW` to the app's window (the window manager's close button); the app exits |
| A4 | Manual package update over 0.4.x | `update`: 0.4.2 installed (`dpkg -i`; AppImage file replaced), launched, quit; 0.5.1 installed over it with the same HOME; relaunched; every running sidecar is byte-identical to the 0.5.1 package's binary |
| A5 | Relaunch | the relaunch after the update, and the relaunch after a crash in `reap` |
| A6 | No Citrate-started process left | after every quit: no process other than PID 1 and the session's own services, and no listening TCP/UDP/unix socket of the app's; at the end: nothing at all in the namespace |

Also checked, from the task brief (supervisor behaviour on the packaged build):

| # | Criterion | Check |
|---|---|---|
| B1 | Service restart under the supervisor | `restart`: SIGKILL the node sidecar; a new process of the same binary appears under the app |
| B2 | Crash recovery and orphan reaping (S0.1) | `reap`: SIGKILL the app only; the sidecars that survive it are recorded; the relaunch must stop all of them, then start its own |
| B3 | Clean shutdown, no ports | part of A6 |

## Safety design (hard rules)

The app never runs in the caller's session. Everything runs as PID 1 of new user, PID, mount,
network, IPC and UTS namespaces with `setsid`, and the harness hides `/home`, `/root`, `/tmp`,
`/var/tmp`, `/run`, `/dev/shm`, `/sys/fs/cgroup` and the GPU nodes behind private mounts, gives
the app a loopback-only network, a private session bus, keyring and an Xvfb display. Ten
isolation probes (with positive/negative controls) must pass before the first launch, or the app
is not started. Signals go only to pids inside the namespace. Details:
[`docs/LINUX_NATIVE_ACCEPTANCE.md`](../../../../docs/LINUX_NATIVE_ACCEPTANCE.md).

## Test-first

1. Red: the harness self-test against a stand-in app packaged as two real `.deb` versions in four
   modes (good, leaks a sidecar on quit, no restart, no orphan sweep), with the restart, quit and
   reap checks stubbed. The three broken modes pass, so the self-test fails (3 modes misjudged).
2. Green: the real checks. The self-test passes: the good mode passes and each broken mode fails
   exactly its own scenario. Revert check: restoring the stubs turns it red again.
3. The self-test runs in CI before the packaged runs, so a harness that stops telling good from
   bad fails the lane (tripwire for the harness itself).

## Out of scope / gaps (stated, not hidden)

- The AppImage's FUSE mount path (setuid `fusermount` does not work in an unprivileged user
  namespace); the AppImage runs with `APPIMAGE_EXTRACT_AND_RUN=1`.
- Anything behind sign-in (Hermes, local model serve, comms/cluster daemons); the S14.1-style
  scenarios with cold model load, noisy logs and Hermes need a member session.
- Peering and sync (offline by design).
- S14.2 (full Linux acceptance) and S14.4 budgets (Linux slice) are v0.5.2 items, not this cut.
