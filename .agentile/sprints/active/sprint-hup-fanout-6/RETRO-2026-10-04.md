## What went well

- **Review-and-finish for unreviewed work.** Fan-out 5 left ten branches with no review, one of them
  a WIP commit with no gates run. Giving each one a single agent that reviewed adversarially, fixed
  what it found and then closed the remaining gaps worked: every one came out gated and fit for a
  PR, and several found real defects in their own predecessor's code.
- **Mutation checks keep finding weak tests.** Reviewers broke guards on purpose in every lane. At
  least eight guards survived the builder's tests (an HTTP probe whose refusal test passed on a
  1 ms timeout, a snapshot checksum, the log-tool bounds, a diff file cap, a session-body branch, a
  decision route's subject filter, a URL credentials check, a calendar fence). Each now has a test
  that kills it.
- **Real tools, not fixtures.** Live T0 tokenizer counts through a sidecar session; parity 21/21
  against the packaged sidecar binary; SearXNG run for real (which found a settings bug the fixtures
  could not); aderyn and medusa from the measured bundle archives; a real faucet binary on a local
  chain; anchoring on two registry versions on anvil; a devnet federated round with an independent
  replay; Chromium-backed axe with colour contrast on.
- **Stacking caught the joins.** Two lanes built Hermes's built-in node MCP entry and two lanes
  persisted in-flight anchors. The stacker joined them on purpose: one in-memory token with a
  server-side read-only scope, and one anchor record that keeps nonce and sender with the measured
  gas cap (one lane's 200,000 would have refused every anchor on the next registry version). The
  runtime stacker found three more joins: shutdown versus reconnect in the MCP host, the new browser
  egress gate blocking the web-subset fixture site, and streaming dropping the usage the Activity
  monitor needs. Each got a red test first.
- **Owner decisions moved.** g2-knowledge flipped on the owner's target the same day, and the
  2026-10-01 decisions (personas, corpus licences, sidecar loop on, strict loader) are applied.

## What went wrong

- **Shared cargo targets.** Nearly every lane hit false compile errors from another worktree's
  artifacts in the shared targets (a kit struct with fields from another branch, missing imports,
  missing rlibs). Lanes lost full test runs and one used a per-package profile override to get
  distinct hashes. Disk limits are why the targets are shared; the cost is real (A55).
- **Lanes interfered with each other.** A cleanup by one lane deleted other lanes' worktrees mid-run
  and lost an uncommitted merge. A stacking lane ran `git stash` mid-merge and had to rebuild the
  merge commit by hand with `git commit-tree`; another ran it during a vitest run. Two lanes collided
  on a loopback port. The A40 brief rule (no `git stash`, no deletes outside your own scratch) was
  not followed (A61).
- **Claims ran ahead of proof.** Reviewers narrowed several builder claims: S1.2 "closed" with no
  embedding endpoint running anywhere; US-6.4 "closed" when a member machine cannot compile a
  rendered template yet; S5.4 "closed" before its packaged click-through; "/health 200 throughout"
  when /health was checked once; a vitest delta of +2 that was +1; a baseline of 1,726 that was
  really 1,839. The words implemented, wired, runtime-proven and ready still need policing (A62).
- **A known-red tripwire stayed red.** The release-pin tripwire failed on `hup/m2-core` and at least
  four lanes reported it as "not mine". The last lane fixed it. A failing CI gate on a shared base
  should go to one named owner the first time it is seen.
- **A misrouted ask.** One lane asked the DGX team for a BGE model and a second server to turn on
  embedding retrieval. Core already bundles `bge-base-en-v1.5`; the work is buildable here (A56).
- **Base formatting drift.** `cargo fmt --all` reformats about 80 untouched files in the runtime, so
  every lane had to revert and format by hand; memories and chain have the same drift (A59).
- **Machine load.** Load averages of 15 to 300 made live Chrome tests flaky, slowed Chrome's
  DevTools start past fixed timeouts, and made Medusa calibration numbers single-machine only.

## What surprised us

- DevTools request interception on current Chrome does not see every kind of connection a page can
  open, so the managed browser now runs behind a connection-level egress gate as well.
- A full T1 Medusa campaign, Slither and Aderyn all pass an unbounded mint with a 500 cap. Only the
  template's own forge unit test catches it.
- `forge test` without `--force` keeps whatever is already in `out/`, which matters when the gate
  binds bytecode to a run.
- The node leaves REVM's block gas limit at its default, so `GASLIMIT` reads `U256::MAX` on 40204; the
  fork had used 30 M until a node-parity test caught it.
- A direct `eth_call` to an agent precompile returns `0x` at every height, because the executor only
  routes top-level calls to accounts with code. The operator checks now use a calling contract.
- The 40204 node puts revert data in the error message, not in `data`.
- k256 can return high-S signatures, which WrappedSALT rejects about half the time.
- InferenceRouter takes native SALT only, and the x402 facilitator signs a different type than the
  ADR pinned. Both are owner calls now.
