# HUP-S6.4: the D-4 deploy gate

Planset: `.agentile/planset/2026-09-30-hermes-upskill/` (00_OVERVIEW D-4 and red-team
corrections 4, 8, 9, 10; 03_TLA_SPECS `DeployGate.tla`; 05_SPRINTS_AND_WPS S6.4).

## What shipped

- **Core gate** (`src-tauri/src/deploy_gate.rs`). Five items, each parsed from raw tool
  output by a deterministic parser: Forge tests (`forge test --json`), Slither (JSON or
  SARIF), Aderyn (JSON), Medusa campaign (console log + call budget), fork dry run (receipt +
  creation tx input + declared precompile use). A tool that is not installed, or that errored,
  is a failing item. Each item carries evidence: counts, SHA-256 of the raw output, run time,
  tool version.
- **Binding.** `initcodeHash = keccak256(bytecode ‖ constructor args)`, the exact `data` of
  the creation tx (`cast keccak` reproduces it). `bindingHash = keccak256(domain ‖ initcodeHash
  ‖ keccak256(solc version, optimizer, runs, EVM version, via-IR))` per red-team correction 8.
  The fork dry run must have deployed exactly this init code.
- **Refusal in `contract_deploy`.** No READY record for exactly this init code → the command
  returns an error naming the hash and every failing item, before the wallet is touched. With
  READY, the ceremony is opened inside `GateStore::open_ceremony` (re-check under the store
  lock), and the command returns the ceremony view plus the gate record.
- **Revocation.** A later NOT READY for the same hash rejects every deploy ceremony still open
  for it (`deploy_gate_submit` → `record_and_revoke`, under the store lock). Latest evaluation
  wins. The store holds at most 64 records in memory; eviction also revokes.
- **Citrate precompiles (correction 9).** Declared `used` or `unknown` fails the fork item, and
  a best-effort bytecode scan for the call-site pattern `PUSH <precompile> GAS CALL*` fails it
  too, since an anvil fork cannot simulate them.
- **Medusa budget (correction 10).** A call budget, not minutes: the campaign must reach its
  budget with zero failed properties; budgets below 10,000 calls fail.
- **UI.** `DeployGateCard` (READY / NOT READY, bytecode hash, compiler line, one line per item
  with evidence) on the wallet review (Signature Ceremony) for a deploy, and on the Contracts
  tab after a refused deploy. The agent's `contract_deploy` result carries the refusal text and
  tells the model to explain it and not retry. Tool description and system prompt say so.
- **Commands:** `deploy_gate_submit(inputs)`, `deploy_gate_lookup(bytecodeHex,
  constructorArgsHex)`, both async through `blocking::off_main` (tripwire green).
- **Typed hand-over for S6.3.** `GateInputs` (Rust) / `DeployGateInputs` (TS,
  `src/agent/deployGate.ts`), bridge `contracts.gateSubmit`. No dependency on the S6.3 branch.

## Not done

- The runtime verifiers that run the tools and call `deploy_gate_submit` (HUP-S6.3).
- Aderyn and Medusa are not installed here; their parsers are tested against hand-written
  fixtures only. Replace with real captures when HUP-S6.1 bundles them.
- `gates.yaml` g3-gate ("DeployGate TLC-green; injected-bug run yields NOT READY") is not
  flipped: the model is TLC-green and a real Slither High yields NOT READY in tests, but the
  end-to-end injected-bug run through the runtime verifiers waits for S6.3.
- Gate records are memory only; a restart forgets them.
- The Citrate-aware fork (HUP-S6.10); until then any contract using Citrate precompiles is
  NOT READY.

## Owner decisions (conservative defaults taken)

- Medusa minimum call budget 10,000 (planset example: 50,000 for template invariants).
- Forge: at least one test must pass; skipped tests are allowed and reported.
- Slither SARIF: a result is High if its rule-id impact prefix is 0 **or** its rule's
  `security-severity` is 7.0 or more; unclassifiable results count as High.
- Aderyn: if `issue_count.high` and the listed High issues disagree, the item fails.
- `PrecompileUse::Unknown` fails the fork item.
- Records in memory only (no persistence), latest evaluation per hash wins, 64-record bound.

## Review (2026-10-01, adversarial pass)

- The Medusa fixtures were named `*.log`, which the repo `.gitignore` ignores, so they never
  reached the branch and the test build failed on a clean checkout. They are now
  `medusa-*.handwritten.txt` (rewritten in the same documented shape; the README says why).
- `GateStore::open_ceremony` kept at most 16 open ceremony ids per hash and dropped the
  oldest silently, so a 17th deploy of the same bytecode left one pending ceremony that a
  later NOT READY could not reach. Overflow now rejects the oldest ceremony instead (test:
  `a_not_ready_record_rejects_every_open_ceremony_even_past_the_per_hash_bound`).
- Verifier-supplied free text (error message, tool version) is cut to 300 chars in the record.
- New mutant killed: a SARIF parser that ignores the `0-` rule-id prefix (test:
  `slither_sarif_rule_id_prefix_alone_marks_high`).
- Reviewer reran: `cargo test --lib deploy` 42 passed; TLC `DeployGate.cfg` no error (17,438
  states generated, 3,378 distinct, depth 15); mutant "NOT READY rejects nothing" in
  `Evaluate` violates `OpenOnlyForReadyBytes` as expected.
