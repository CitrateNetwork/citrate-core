# Journal: a reader window with no commands

The Contract reader is a window that can do almost nothing on its own, on purpose. The pop-out
capability from S5.4 grants bridge events and no app commands, and that rule stayed. So the
reader had to become a client: it asks, and the main window answers after checking the
request again. That shape paid for itself twice.

First, writes. The reader never needed a signing path, because the main window already has
the one path that exists: the WalletReviewModal over a pending ceremony. A write from the
reader is a request that ends in the same review every other write ends in. The reader only
learns "proposed".

Second, explanations. The contract's source is text written by whoever deployed it. Sending
it into the chat thread as if the member typed it would have handed a stranger's comments to
an agent with tools. Instead the explain turn runs on the same provider with the source fenced
as untrusted data and every tool call answered "not available". A test asks the provider to
call `contract_deploy` mid-explanation and checks the refusal text it gets back.

The end-to-end run caught nothing, which was the useful result: the folder multipart for
kubo was the part most likely to be wrong (directory parts, percent-encoded paths, which line
of the add stream is the root), and listing the pinned CID showed `assets` and `index.html`
at the root on the first run. The one surviving mutant was in the verified-state rule: the
tests only fed the parser consistent explorer answers. An answer with `verified: true` and a
partial match type now has its own test.
