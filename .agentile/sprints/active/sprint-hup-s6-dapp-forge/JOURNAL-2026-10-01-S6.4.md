# Journal: the deploy gate is a lock, not a lookup

The first version of the gate was a lookup. `contract_deploy` asked the store "is this hash
READY?", got yes, and opened the ceremony. All the parser tests were green and every mutant
of the parsers died. Then writing `DeployGate.tla` forced a question the tests had not asked:
what happens to a ceremony that is already open when the verdict changes?

With a plain lookup, nothing. A member could get READY, open the review, then the verifiers
re-run on the same bytes and find a failing property. The record flips to NOT READY, and
the review still sits there, approvable. The planset says "NOT READY never signs". A lookup
only gives "NOT READY never opens".

The fix has two parts. The model shows that each is needed (mutants M03 and M04):

1. A NOT READY record rejects every ceremony still open for its hash.
2. The re-check and the ceremony request happen under the same lock as the record write.
   Without the lock, a NOT READY can land between "checked READY" and "ceremony opened". It
   then finds nothing to revoke, and the new ceremony opens on bytes that are no longer READY.

Neither part would have come from the example tests alone. Both came from stating the
invariant over the signed log rather than over the guards, which was the lesson of the
earlier fan-out's S2.7 vacuity episode.

Smaller notes:

- Real tool output beats remembered formats. Slither's SARIF marks every result `warning`;
  the impact is in the rule-id prefix (`0-1-arbitrary-send-eth`) and in `security-severity`.
  A parser written from memory would have read `level` and passed a High.
- The fixtures are real captures where the tool exists here (forge, slither, anvil) and are
  labelled hand-written where it does not (Aderyn, Medusa). The labels are in the file names,
  so the gap stays visible.
- A naive precompile scan (any PUSH of 0x0100..0x013F) would block ordinary contracts, because
  those values are also common memory offsets. The scan only looks for the call-site shape and
  can only add a failure. The declared `citratePrecompiles` covers the rest, and `unknown`
  fails.
