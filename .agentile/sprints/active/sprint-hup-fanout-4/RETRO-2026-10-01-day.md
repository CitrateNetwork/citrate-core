## What went well

- **Forty-four PRs, one CI pass each, nothing excluded.** Every lane reached pass-after-fixes, so
  the needs-work exclusion rule never fired. The stacking lanes opened every PR exactly once, after
  the gates were green at the top.
- **Reviewers earned their keep again.** Every reviewer ran its own mutants rather than trusting the
  builder's list, and in at least twelve lanes they found guards that no test held: removing them
  left the suite green. Each became a test, red first. Two reviewer finds were real defects found
  by reading, not mutating: one in the workbook reader (S10.2) and one in how a browser approval is
  tied to what the member was shown (S5.1). Both are fixed on the branches.
- **Model checking found design gaps that tests had missed, four times.** FlRoundGate showed an
  adapter could stay loaded after being re-gated against another base model. AnchorSettle showed a
  second approval card for a day whose anchor was already in flight. LearnRestart showed a lost save
  could reopen a rejected proposal. DaemonBudget showed nothing new, but writing it led the S10.3
  reviewer to the pause gap that the model abstracted away (A44).
- **A cross-repo golden caught a real disagreement.** S1.5's quote in core and the sidecar's worst
  case differed by 48 micro-USD because one side counted an empty system message. The shared golden
  fixed it in both repos.
- **The stacking lanes did integration work, not just merges.** Two conflicts were semantic. S2.1
  scoped the toolchain to session grants inside the sidecar process, while S1.9 moved the toolchain
  into a worker process; the runtime stacker added a backend trait so the worker receives the grant
  document with every call, with three tests against the real worker binary. S4.3 and S4.4 each set
  the same MCP allowlist variable, so the last one silently won; the core stacker wrote a test first
  and joined them into one file.
- **Safe defaults held everywhere.** Every new capability is off for members until they act: browser,
  search, MCP servers, file tools, learning publish, escalation (cap $0), anchors, daemons,
  telemetry, component updates (empty key slot). Owner placeholders are marked in code, UI and docs.
- **Real runs, not only fixtures, where the machine allowed.** Claude Code called the node MCP
  server over HTTP; the browser lane drove real headless Chrome; the corpus imported into a real
  mem-mcp and searched; decide() scored 12/12 on Gemma 4 E4B through the bundled llama-server;
  hello-mint deployed, read back and pinned on anvil and a throwaway kubo; the T0 eval produced
  scorecards.
- **Disk stayed above the floor.** About 82 GB free at launch, about 33 GB at the end, never near
  10 GB.

## What went wrong

- **Shared scratch paths collided between agents, four times.** The S7.3 builder used
  `/tmp/n4mut.bak` as a mutation backup, which the S3.4 lane was also using, and deleted it. Two
  reviewers shared `scratchpad/n4-rv-bak`. The S3.5 reviewer cleaned up with a glob that matched
  other reviewers' files. The two stacking lanes both wrote `n4-stack-union.py`. Every affected agent
  checked its tree against git before committing and the stack tops are green, but this was luck plus
  diligence, not design. (A40)
- **Mutation helpers left mutants in working trees.** Two builders' helper scripts restored from the
  wrong path and left mutants in place; both noticed and restored by hand before committing. One
  builder ran `git stash` in a worktree, which writes to the repo-wide stash other agents share, and
  another ran `git checkout --` on a file it meant to keep. (A40)
- **Overlapping briefs produced duplicate concepts.** No sidecar file tools existed, so two lanes
  built them: S2.1 added `file_list/read/write` (no undo) and S2.9 added `fs_write/edit/delete/rename`
  (with checkpoints). Both now ship in one sidecar under different names. The MCP allowlist was the
  same story, fixed at stacking. The brief assigned stories, not shared concepts. (A39, A42)
- **Several claims were wrong or overstated before review.** One "clippy clean" was false on the
  pushed head. Two "complete" claims hid partial acceptance criteria (Sheets in S10.2; Hermes running
  view calls in S6.7). Two runtime counts were off by two. One builder said a browser block was
  enforced when it was only displayed. Most builders' mutation lists were narrower than they read.
  The reviewers caught all of these, which is the point of the reviewers, but A30 (counts only from
  the pushed tree) is not enough on its own. (A41)
- **The shared cargo targets produced stale failures in almost every lane.** Tests read paths baked
  into binaries from other worktrees; doc tests found rlibs replaced mid-run. The touch-and-rerun rule
  worked, but it cost time in every lane and blocked one reviewer's doc-test step entirely. (A41)
- **One High is still open.** It needs two lanes together to reach, which is why neither lane's review
  could see it whole. The red-team pass on the stack tops is what found the combination. (A37)
- **T1 evaluation could not run.** The 27B model hit Metal out-of-memory three ways because the app's
  own llama-server was holding a large model. The scorecards are T0 only, and g2-knowledge has a
  baseline, not a pass. (A46)
- **Eval datasets were edited in place by three lanes.** S9.4, S10.3 and S4.3 each appended items to
  `toolcall-v1` and `injection-v1` because the tripwires require every tool to be covered. The
  datasets' own note says a change means a new version. (A50)

## What surprised us

- **AgentSBT is deployed on 40204.** The brief said it was not. It was missing only from core's
  generated address book. What actually blocks members is that no OrganizationSBT exists and
  `mintAgent` is owner-only. A SkillRegistry with code is also at the address-book address.
- **The training coordinator has no endpoint to start a round.** Jobs come from an operator catalogue
  at boot. "Start" can honestly only record the member's approval until the device worker exists.
- **srcdoc, blob and data iframes inherit the parent CSP,** so the planned sandboxed-srcdoc widgets
  would have run in jsdom and dev mode and never in the packaged app. Widgets now use their own URI
  scheme with their own CSP header.
- **The QA scorer's abstention markers missed the phrasing its own prompt asks for.** The first T0 run
  scored 0 of 150; the correct abstentions were scored as failures. Fixed test-first; the re-run at
  temperature 0 produced identical answers and a 10% pass, all from correct abstentions.
- **Adding one agent tool touches seven tripwires** across two repos: annotations, the gates test,
  both eval datasets, the eval runner's write list and tool count, and the parity fixture with its
  cross-repo sha256 pin.
- **The main-thread tripwire matches functions by name,** so a new blocking method called `remove` or
  `join` made unrelated sync commands fail it. Two lanes renamed methods.
- **The knowledge corpus is 35 MB** because the sync bundle format stores node text as JSON number
  arrays.

  merged clean only because the stacker merged the updated base forward rather than assuming the old
  SHA.
- PRs carry neutral wording. Lane security notes went only into returned reports and from there into
  the private tracker; the public PR text names follow-ups without specifics.
