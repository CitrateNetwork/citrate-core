# A capability file does not limit app commands until the app has its own ACL

**Dek:** "Least privilege for a pop-out" needed a change to the main window's permissions, because
Tauri lets every local window call every app command until the app defines a command ACL.

## Context

Overnight fan-out, lane n3-popouts: HUP-S5.4 (pop-out window framework) and HUP-S7.6 (Activity
monitor with Stop). The brief asked for a pop-out capability with no shell and no fs.

## What happened

Writing `capabilities/popout.json` was easy. Before trusting it I read Tauri 2.11's invoke path
(`webview/mod.rs`): app commands are ACL-checked only when the app ships an app manifest, or when
the caller is a remote origin. So a capability file alone could not give a new local window fewer
app commands than the main window has; the app needed its own command ACL first.

The fix is `src-tauri/permissions/main-window.toml`: one permission listing all 173 registered
commands, granted only by the main window's capability. No `build.rs` change was needed; a
`permissions/` dir is enough for `tauri-build` to turn the app ACL on. Two tests keep it honest: the
list must equal `generate_handler!` exactly, and Tauri's own resolver (`tauri-utils`, test-only)
must give every command to `main` and none to any `popout-*` label.

The Stop path did not exist either. The sidecar session had a stop route nobody called, and the
in-app loop had no abort. I added an `AbortSignal` to `SendOpts`, a store-level race so Stop returns
the chat at once even when a model request is wedged, and a drain in the sidecar provider so the
next turn never reads the stopped turn's trailing `done`. The first version would have let the old
poll loop consume the new turn's events; the serialisation test now pins that.

## What I learned

- In Tauri 2, a capability that omits app commands proves nothing until an app ACL exists. Check
  the runtime's invoke path, not just the config schema.
- Turning the ACL on is a contract change for every lane: a new command must be added to
  `main-window.toml` or the main window cannot call it. The test makes that a red build, not a
  runtime surprise.
- Mutation runs found one stop check that no test could reach; it was redundant and is gone.

## What I'd do differently

Read the framework's enforcement code at the start, not after writing the capability file.
